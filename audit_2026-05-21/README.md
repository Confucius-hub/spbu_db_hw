# Аудит членов СРО — реестр договоров на 21.05.2026

Второй прогон по той же методике, что и папка `../audit/`, но на новом исходнике —
реестре договоров **на 21.05.2026** (89 компаний, 442 договора).

## Исходник

`source/contracts_registry_2026-05-21.xls` — выгрузка реестра договоров членов СРО
(BIFF8). Колонки: член СРО, ИНН, статус в СРО, заказчик, вид закупки, стоимость
работ, оплачено, **штрафы/пени/неустойки**, статус исполнения и др.

## Что переиспользовано

Из 89 компаний **65 уже были в прошлом аудите** (`../audit/`) — их веб-данные
(статус НОСТРОЙ + дела по подряду 2025+) перенесены в `collected_data.json`
с пометкой `data_note: "перенесено из прошлого аудита"`. Контрактные цифры
(число договоров, суммы, штрафы) пересчитаны заново из ЭТОГО файла.

Реально новых компаний — **24**, по ним веб-данные собирает браузерное
расширение (см. `EXTENSION_COMMAND.md`, 3 батча).

## Процесс

```
1. source/*.xls ──> companies.csv (агрегация по ИНН)
2. collected_data.json (65 перенесено + 24 от расширения)
                   └──> build_report.py ──> audit_report_corrected.xlsx
```

## Файлы

- `build_report.py` — пайплайн (копия из `../audit/`, логика та же).
- `companies.csv` — 89 компаний (имя, ИНН, вид, договоры, сумма, штрафы).
- `collected_data.json` — веб-данные по ИНН (65 перенесено, 24 ожидают).
- `EXTENSION_COMMAND.md` — команда расширению по 24 новым компаниям.
- `source/contracts_registry_2026-05-21.xls` — исходный реестр.
- `audit_report_corrected.xlsx` — результат.

## Модель риска (та же)

- **Высокий** — НОСТРОЙ приостановлен/исключён; ОДО не установлен; есть дела по
  подряду 2025+; крупные штрафы (≥ 1 000 000 ₽).
- **Средний** — небольшие штрафы (< 1 000 000 ₽); спорные данные.
- **Низкий** — НОСТРОЙ действителен, ОДО установлен, дел нет, штрафов нет.
