# Проверка членов СРО — пересборка отчёта (исправленная методика)

Папка содержит инструмент пересборки итогового отчёта по фидбэку к
`audit_report_FINAL_1.xlsx`. Цифры по контрактам (этапы 1–2) подтверждены как
верные и переносятся как есть; исправляются веб-данные (этапы 3–5).

## Что исправлено относительно первой версии

| # | Проблема в v1 | Исправление |
|---|---------------|-------------|
| 2 | Статус НОСТРОЙ у всех «действителен» | Статус берётся пер-компанийно (действителен / **приостановлен** / исключён) |
| 3 | Считались все дела за 2025+ | Сначала фильтр по категории «**…подряда**», потом по дате ≥ 01.01.2025. Источник — Rusprofile (там категория явная) |
| 4 | «Хаотичное» описание спора | Описание = **№ дела + сумма иска + роль** (истец/ответчик/третье лицо) |
| 5 | Ссылка вела на главную kad.arbitr.ru | Ссылка на **конкретную карточку** дела |

## Почему нужен браузерный расширение

Из облачного окружения исходящий доступ к сайтам заблокирован сетевой
политикой (`403` на любой внешний URL). Поэтому веб-данные собирает
**браузерный расширение Claude** (у него есть реальная сессия в браузере),
а этот пайплайн их обрабатывает.

## Процесс

```
1. companies.csv ──┐
                   ├──> build_report.py ──> audit_report_corrected.xlsx
2. collected_data.json (от расширения) ──┘
```

1. **Сбор данных.** Скопируйте команду из `EXTENSION_COMMAND.md` в расширение.
   Оно вернёт JSON по компаниям (НОСТРОЙ + дела по подряду 2025+).
2. **Подстановка.** JSON кладётся в `collected_data.json`
   (формат одной записи — в `collected_data.example.json`).
3. **Пересборка.** `python3 build_report.py` → `audit_report_corrected.xlsx`.

Пока `collected_data.json` пуст, отчёт собирается как «превью»: структура
готова, веб-ячейки помечены «⏳ ожидает данных».

## Файлы

- `build_report.py` — пайплайн пересборки (логика риска и структура листов).
- `companies.csv` — выверенная база 67 компаний (имя, ИНН, вид, контракты, сумма, штрафы).
- `EXTENSION_COMMAND.md` — готовая команда для браузерного расширения.
- `collected_data.json` — данные расширения (на вход пайплайну).
- `collected_data.example.json` — пример формата (реальное дело ЭНТЭЛ из скриншота).
- `source/audit_report_FINAL_1.xlsx` — исходный отчёт v1.
- `audit_report_corrected.xlsx` — результат.

## Модель оценки риска (этап 5)

- **Высокий** — приостановлен статус НОСТРОЙ; ОДО не установлен; есть дела по
  подряду 2025+; крупные штрафы (≥ `BIG_FINE`, по умолчанию 1 000 000 ₽).
- **Средний** — небольшие штрафы (< `BIG_FINE`); спорные/неподтверждённые данные.
- **Низкий** — НОСТРОЙ действителен, ОДО установлен, дел по подряду нет, штрафов нет.

Порог `BIG_FINE` правится в начале `build_report.py`.
